# Changelog

All notable project changes are tracked here.

## Unreleased

- No-speech recordings now return to idle immediately instead of parking the overlay on `WAI` and then flashing `ERR`. A microphone keeps producing PCM in a quiet room, so "captured bytes" cannot tell silence from speech: `Recorder` now tracks the session's peak amplitude (`SessionPeak()`, reset by `Start()`, tail included), and `finishRecordingSession` skips the ASR round-trip when the whole recording never rose above `silencePeak` (~-46 dBFS) - the same fast path already used for a zero-byte recording. As a second layer, the `doubao_url` backend now reads `X-Api-Status-Code` from the query endpoint: `20000003` ("no valid speech") and `20000000` are terminal (the former publishes an empty final), only `20000001` keeps polling, and a new `PollTimeout` (12s) publishes an empty final instead of polling forever. Finally, the streaming backend's final wait gives up after a 4s no-speech grace when the backend never produced a single partial hypothesis, and only shows `ERR` when partials arrived but the final never did. Regression tests: `TestFinishRecordingSessionSilentAudioSkipsASR`, `TestFinishRecordingSessionFinalTimeoutWithoutPartialIsNotAnError`, `TestFinishRecordingSessionFinalTimeoutWithPartialIsAnError`, `TestFinishRecordingSessionNoSpeechGraceEndsEarly`, `TestRecorderSessionPeakTracksLoudness`, `TestRecorderSessionPeakIncludesUndrainedTail`, `TestURLASRNoSpeechPublishesEmptyFinal`, `TestURLASRProcessingThenFinal`, `TestURLASRPollBudgetExpiresWithEmptyFinal`.

- Fixed the regression where every normal recording was treated as silent, so streaming ASR partials still appeared but no final transcript was ever produced or pasted (the overlay stopped at `STP`/`WAI` with no text). The empty-recording fast path added in the previous fix keyed off the byte count returned by `Recorder.Stop()`, but that value is only the tail the streaming reader had *not* consumed yet - `streamAudio` keeps the capture pipe drained while the user speaks, so `Stop()` normally returns zero bytes even for a long, loud utterance. `Recorder` now tracks the total bytes captured for the session (streamed chunks plus the drained tail) and exposes `CapturedBytes()`; `finishRecordingSession` skips the ASR round-trip only when that total is zero. Truly silent recordings still take the fast path. Regression tests: `TestRecorderCapturedBytesSurvivesStreamDrain`, `TestRecorderCapturedBytesCountsUndrainedTail`, `TestFinishRecordingSessionStreamedAudioStillSendsFinal` (which also closes the previously documented but missing `TestNonEmptyAudioStillDispatchesTranscript` gap).

- Fixed silent recording leaving the `WAI` overlay stuck. When a recording captured no audio (muted mic, hotkey released before any sample landed, the user said nothing), the offline `SendAudio` path returned without closing `Final`/`Done`, the streaming backend ignored empty final responses, and the URL backend kept `lastText` set to the previous session's transcript - so the voice pipeline either waited the full 15s ASR timeout or re-pasted the previous transcript. `finishRecordingSession` now skips the ASR round-trip entirely for empty recordings (no `SendAudio`, no 15s wait, no `Final`/`Done` indirection) so the overlay dismisses within milliseconds. All three backends still publish an empty final result and clear `lastText` as a defence-in-depth measure, and the URL backend additionally drains its result channel on `Close()` so the consumer goroutine exits cleanly. Regression tests: `TestFinishRecordingSessionEmptyAudioSkipsASR`, `TestOfflineASREmptyAudioFastPath`, `TestURLASREmptyAudioFastPath`, `TestASRClientEmptyFinalClosesAndResets`, `TestASRClientNonEmptyFinalKeepsText`.

- Fixed duplicate text output (one utterance pasted twice). Two independent causes were removed: (1) the single-instance lock was only taken in daemon mode, so a TUI instance and a background daemon could run side by side, each registering the same global hotkey and each pasting the recognized text; the lock is now taken in every mode. (2) In `toggle` mode, pressing the hotkey again while the stop buffer was still running finished the in-flight session - dispatching its transcript - and then started a fresh recording, so a nervous double press could paste the same sentence twice. The press now cancels the pending stop and keeps the same session recording, exactly like `hold` mode; the now-unused `restartRecording` path was deleted. Regression tests: `TestTogglePressDuringStopDelayKeepsRecording`, `TestAcquireSingletonRefusesLiveTUI`, `TestAcquireSingletonReplacesDaemonForTUI`.

- Recording overlay redesigned around a call-indicator style waveform. The bars moved **below** the status label (two-row capsule, 240x70 at scale 1) instead of sitting next to it, and they are wider (4 px) and roughly twice as tall (26 px) so the waveform is the visual focus. A new animator (`plugins/overlay/animate.go`) tracks a smoothed energy envelope gated on speech level and lets mirrored oscillators dance inside it: the bars swell as soon as audio arrives, keep moving while the user talks, and ease flat when the room goes quiet - reacting to the voice instead of scrolling old samples from left to right. Rendering moved into a backend-agnostic renderer (`plugins/overlay/render.go`) shared by the X11 and Wayland backends and the tests, which adds a soft blue outer halo, a blue rim light that brightens with the audio, a pulsing indicator halo, a dark blue-gradient capsule and cyan-tipped bars. The overlay window is a fixed transparent size, so the capsule keeps the same screen margin whether it is in the compact or the two-row state, and the recording capsule no longer jumps shape when the first amplitude sample arrives. The bitmap font was completed to printable ASCII (previously `IDL` rendered as `ID`). `JT_OVERLAY_PREVIEW=1 go test ./plugins/overlay/ -run TestRenderPreviewPNG` writes review PNGs of every state, of the animation frames and of the font.

- Recording overlay now shows the live audio waveform plus streaming ASR partial text alongside the existing REC indicator. The Recorder keeps a 64-sample ring of normalized peak amplitudes updated every PCM chunk; the voice plugin publishes them to `TUIVoiceStatus.LevelSamples` at ~30 Hz. The overlay subsamples to 24 bars and renders `dot + label + waveform` in a wider capsule (220 px at scale 1). When the WebSocket backend returns a partial result it is published to `TUIVoiceStatus.PartialText` and shown in place of "REC", truncated to the latest 30 runes. The `doubao_url` and offline backends keep showing "REC" + waveform (no partial text). The `UR` partial pipeline is wired but unused by anything other than the WebSocket backend.

- Added a Linux/macOS system tray indicator (`plugins/tray`) that shows a colored status icon (grey idle, yellow connecting, red recording, orange stopping, dark red error, green/orange gesture arrows) and exposes Show TUI, Open Config, Open Config Dir, and Quit menu actions. The plugin runs only in daemon mode (`--no-tui`) and registers as a `org.kde.StatusNotifierItem` on DBus, which the GNOME `AppIndicator` extension and KDE Plasma render natively.
- Added `make icons` / `make install-desktop` / `make uninstall-desktop` to install the desktop launcher icon and `.desktop` file into `~/.local/share/applications/` and `~/Desktop/`. The `.desktop` entry launches the binary in daemon mode, so clicking the icon or selecting it from the application menu starts Just Talk with the tray icon.
- Added a `flock`-based single-instance lock (`$XDG_RUNTIME_DIR/just-talk/just-talk.lock`). The lock now covers every mode (TUI and daemon) and records `<pid> <mode>`, because two live instances both register the global hotkey and both run the record -> ASR -> paste pipeline, which pastes one utterance twice. A launch replaces a running background daemon automatically; a running TUI is reported instead of killed, so its terminal is never left in raw mode. Stale locks from a crashed previous instance are automatically reclaimed.
- Removed the `~/.config/systemd/user/just-talk.service` autostart unit. Just Talk is now meant to be launched on demand from the desktop; users who want autostart can add their own systemd `user` unit or place a startup script in `~/.config/autostart/`.
- Wayland/evdev backend now listens to `NETLINK_KOBJECT_UEVENT` for input device hotplug. Keyboards (including Bluetooth HID devices that pair after startup, USB devices plugged in after launch, etc.) are picked up immediately as `/dev/input/eventN` nodes appear, without requiring a restart of just-talk. Device removals are also handled so unplugged devices do not stay in the poll set.
- Added multi-tap hotkey gestures for chat/coding workflows. While idle, quickly tapping the voice hotkey twice presses Enter in the focused window (the most frequent action, so it gets the easier gesture), and tapping it three times retracts the just-pasted text (`Ctrl+Z` by default, or `Ctrl+A` then `Backspace` with `undo_action = "clear"`). A gesture that starts while a recording, ASR finish, or paste is already in flight is ignored. The overlay briefly shows a `⏎` return arrow or a `↶` retract arrow instead of the recording indicator; the return glyph was redrawn so it no longer reads as a `J`. Controlled by `voice.double_tap_send`, `voice.triple_tap_undo`, `voice.undo_action`, and `voice.multi_tap_ms` (the shared multi-tap window, default 500 ms, clamped below `stop_delay_ms`).
- Added a new `doubao_url` ASR backend that uses the Doubao/Volcano `auc` submit+query HTTP endpoint with a single `x-api-key`. This is the official replacement for the streaming WebSocket `sauc` AppKey/AccessKey credentials and works with the seedasr.auc token pair. The backend buffers PCM, wraps the recording in a WAV container, base64-encodes it, submits it, then polls the query endpoint until the final transcript is returned. No partial results are emitted, but latency from stop to text is typically under three seconds.
- Removed the `press` hotkey mode and its associated LLM polish pipeline. The voice plugin now supports only `hold` (press and hold to record, release to stop) and `toggle` (press once to start, press again to stop). The recording status overlay continues to display the `REC` indicator while a recording is in flight, matching the pre-`press` behavior.
- Added an optional OpenAI-compatible LLM polish step (`[llm]` in config). When `mode = "press"` and the recording was started via a short press, the ASR result is routed through the LLM before being pasted. LLM failures fall back to pasting the raw ASR text and surface a one-line warning.
- Added a hotkey capture mode in the TUI: pressing `c` while editing the 热键 field listens for the next global key combo and stores it as the new hotkey, replacing manual text input.
- Clarified README build and install setup steps for the repository directory and `~/.local/bin` PATH.
- Restricted voice hotkeys to non-text global shortcut keys, rejecting letters, digits, punctuation, Space, and similar text-producing keys.
- Avoid duplicate auto-submit on KDE Plasma by using uinput directly and not writing the Wayland primary selection there.
- TUI is now the default startup mode.
- Added persistent usage statistics for total sessions, recognized characters, average speed, and recent speed.
- Added configurable ASR hotwords.
- Added TUI help toggle with `h`.
- Improved Wayland clipboard and auto-submit behavior with `wl-copy` and `wtype`.
- Added Linux recording status overlay for X11 and Wayland.
- Added macOS support for global hotkeys, native recording, clipboard, auto-submit, recording status overlay, and environment checks.
- Removed non-cgo macOS fallback builds; Just Talk now requires cgo for native platform integration.
- Replaced the old Claude-specific agent guide with `AGENTS.md` and clarified build documentation.
- Improved toggle and hold hotkey behavior for fast repeated key presses.
- Show ASR connection and final-result timeout errors in the status UI/overlay instead of immediately falling back to idle.
- Added transient `Esc` cancel and `R` retry hotkeys while recording or showing retryable errors.
- Improved X11 overlay placement on multi-monitor setups and switched X11 rendering to an ARGB window for smoother rounded corners.
- Fixed a Wayland overlay shutdown race that could crash while closing the app, and surfaced Linux `arecord` microphone/device failures in the UI.
- Made `Esc` cancel active overlay states, including the final ASR wait state, and suppress output from canceled pending sessions.
- Improved Wayland overlay rounded-corner antialiasing, especially on KDE Plasma.
- Added `just-talk --install` and `make install` to install the binary into `~/.local/bin`.
